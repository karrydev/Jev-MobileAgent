# Jev-MobileAgent 开发路线

更新：2026-09-25。按用户明确的独立 App 要求修订；产品边界见 [ADR-0003](adr/0003-standalone-android-runtime.md)，验收要求见[首版规格](../.scratch/mobile-agent-v1/spec.md)，进度及依赖见[任务索引](../.scratch/mobile-agent-v1/index.md)。旧研究、设备桥与服务器部署文档保留为来源，不再决定交付形态。

## 1. 交付目标

用户安装 APK，在 App 内配置 VLM/Jev 的模型与 Key，开启所需系统权限后，仅用手机及互联网即可发起、执行、核验和恢复任务。编排、动作与任务记录在手机内，模型通过供应商 HTTPS API 调用；无需用户自建服务、电脑、USB、ADB、设备桥地址或 Token。独立 App 不等于离线大模型。

首版保持单用户、单手机、同一时间一个任务。暂停和取消阻止后续动作；中断、进程重启、权限变化或人工介入后重新观察、核对历史并经用户确认恢复，UNKNOWN 不自动重放。应用切换到目标 App 后仍需有可达的暂停/取消入口；系统终止、锁屏或缺少权限时安全暂停，不承诺绕过 Android 限制。

## 2. 现状与复用边界

01–20 的原版基线、角色提取、裁剪、设备能力、桥接式 VLM 闭环和双端恢复结果保留，不重写为失败或批量重新领取。当前 APK 仍依赖 Python 设备桥，尚未满足独立产品要求。

| 已有资产 | 当前处理 |
| --- | --- |
| Android 无障碍树、截图、输入/节点/手势、坐标、执行门禁和动作日志 | 直接复用，修改运行入口时做相关回归 |
| `agent_core/vlm/` 的角色、提示词、历史行为；`agent_core/` 的候选与核验语义 | 按需移植到现有 Android 工程，以样例和外部行为对照；不追求逐行翻译 |
| `services/android_bridge/` 的状态、预算、恢复与报告行为 | 提取手机内闭环必需部分；双端配对和网络命令交付不成为手机内新增架构 |
| Python 参考入口、离线评测、样例、来源与许可证 | 保留作开发工具和对照，运行产品不需要它们 |
| 本地部署控制器与 19/20 证据 | 历史实现证据；不能代替 26/27 的手机内运行验收 |

迁移与策略优化分开：先以原角色行为建立手机内仅 VLM 基线，再逐项加入 Jev 选择、树核验和按需规划。只重跑受运行时变化影响的检查，不重复整套初始化、目录裁剪或无关研究。

## 3. 当前推进顺序

编号是稳定身份，不表示执行先后。继续使用 28 个编号，当前有 8 项未完成；不再保留服务器资源的人工作业。

| 批次 | 任务 | 放行结果 |
| --- | --- | --- |
| 当前可并行 | 21 已提供 Jev 凭据的有限探针；26 App 内仅 VLM 闭环与模型设置 | 真实 Jev 访问证据；用户在 App 填 Key 后手机独立执行任务 |
| 26 后 | 22 手机内 Jev 影子运行；27 手机内恢复与无电脑运行 | 影子建议的独立报告；App/服务/手机重启与网络/权限中断后手动恢复 |
| 逐项优化 | 22 → 23 Jev 受控执行 → 24 树核验 → 25 按需规划 | 每次只改变一项策略，与前一版独立 App 做同条件对照 |
| 汇合交付 | 25 + 27 → 28 最终 APK 验收 | 最终安装配置、真实任务、恢复、版本及费用报告；无项目服务或开发工具依赖 |

21 与 26 可同时开发；22 与 27 仅在修改文件互不冲突时并行，同一 App 运行入口与持久化指定唯一编辑者，必要时串行。同一物理手机由协调者串行控制，测试后锁屏。具体领取遵循[并行协作](parallel-development.md)。

用户已提供 VLM/Jev 统一测试凭据文件。先用已有权限和预算完成可独立工作，只在确有账号、额度或手机授权缺口时说明获取方式并请求用户；不再询问服务器、SSH 或 GPU。

## 4. 实现与共享边界

| 工作范围 | 归属与约束 |
| --- | --- |
| 手机内任务与模型 | `android-app/`，一个任务入口、一个本地状态来源、VLM/Jev 分开配置；保留原规划行为直到 25 |
| 设备能力 | 复用 Android 观察、截图与执行，动作绑定观察版本和坐标，服务生命周期与用户控制统一 |
| 恢复与证据 | 本地任务/动作持久化、费用和 usage 缺失、独立结果；旧任务代次不能派发，恢复不重置预算 |
| Python 参考与评测 | `agent_core/`、`services/`、`eval/` 继续提供样例与对照，不承担正常用户运行 |
| 契约、文档与合入 | 协调者统一管理；内部语义延续，设备桥传输格式不要求在手机内照搬 |

先确定本次切片必要的观察、完整动作、执行回执、核验、任务控制与轨迹语义再修改消费者。不要新增通用插件平台、第二套编排框架或 APK 内 Python HTTP 桥。已有 UI 可逐步适配，正常产品入口清楚表达模型配置、权限、目标、任务状态、暂停/取消和恢复；桥接调试功能与它隔离。

Key 由用户在 App 输入，保存在 Android Keystore 支持的加密存储中；只发送到用户配置的相应模型 HTTPS 端点，不进入日志、备份明文、导出或 APK。开发 env 是测试准备手段，不能成为 App 的运行依赖。

## 5. 验收与证据

保留原真机单模型、AndroidWorld 四角色、提取版参考后端及旧桥接 App 基线。新的策略比较以独立 App+VLM 为起点，逐项对比增加 Jev 选择、树核验、按需规划；不同运行入口的差异不计作策略收益。历史失败仍作为失败保留。

每次记录 SHA、APK、模型/提示词/配置、任务初始状态、设备/ROM、预算、重复编号和独立判据；失败、取消、重试和视觉回退计入总尝试。缺失 usage 与未知费用明确保留，不补造费用或预设收益。实测前冻结任务、次数、预算与回归放行规则，改变条件时指出失效的对照。

- 契约和回放证明客户端控制逻辑，覆盖旧观察、重复动作、非法模型输出、迟到响应、预算与 UNKNOWN。
- 实际 API 和真机证明能力，回放不能代替真实供应商协议或 Android 行为。Jev 影子报告不能证明它控制后的任务成功率。
- 最终用户结果通过目标页面状态或独立任务判据验证，模型自述、HTTP 200、回执或构建成功均不等同任务完成。

26 验证手机内真实 VLM，27 验证中断和恢复，28 在最终 APK 上重做受集成影响的用户验收。安装后由 App 设置凭据，拔掉 USB、关闭无线调试/ADB reverse、停止所有项目服务，再完成任务；测试后可重新连接导出手机本地证据。原始截图、树与响应仅留本机，公开仓库只保留脱敏材料。ADB 可用于开发安装、故障注入准备和事后取证，不能参与产品执行闭环。

AndroidWorld、AndroidControl、Mobile-Eval-E 的既有素材与独立判据按相关票复用；不为了改运行位置扩建评测框架或重新搭建完整 MobileWorld。最终用户只拿到 APK、配置/权限/恢复说明与明确限制，不需要部署手册。
