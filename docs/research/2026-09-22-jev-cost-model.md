# MobileAgent v3.5 接入 Jev：成本核算与优化空间

更新日期：2026-09-22。本文基于已核查的源码与官方价格说明核算方式；没有调用付费 API 或运行手机任务。不预设降本比例、速度或成功率目标。项目范围见[当前决策](../project-direction.md)。

## 1. 可以判断的优化空间

主要机会是将布局树可充分描述的动作选择和结果核验交给代码或 Jev，减少视觉模型调用及其图像、历史和输出开销。按需规划、减少无效重试也可能降低费用，但必须在任务完成质量可接受的条件下测量。

Jev 单价低不等于整段任务一定更便宜。树可能很长，选择与验证需要不同观察，视觉回退时已经发生的 Jev 成本仍要计入；如果错误动作增加步数、重试或重新规划，也会抵消节省。现阶段无法给出可信的项目降本百分比。

## 2. 按实际 v3.5 入口建立基线

| 入口或实现 | 计费结构 | 对照要求 |
|---|---|---|
| 原 `mobile_use` 真机示例 | 当前截图、近轮图文历史及动作摘要送给单个 GUI-Owl；下一轮继续决策，没有独立四角色 | 记录每次实际请求、历史长度和重试，不假设每步有独立规划与反思费用 |
| 原 AndroidWorld 四角色 | Manager、Executor、ActionReflector 和按分支调用的 Notetaker | 逐角色记录请求；终止、格式错误、任务特例等分支会影响次数 |
| 提取后的生产编排 | 从 v3.5 复用角色，替换环境访问，再逐步增加树和 Jev | 先建立仅用原 VLM 的生产基线，再分别比较设备桥、JevSelector、树验证、按需规划的增量 |

来源：[真机入口](https://github.com/X-PLUG/MobileAgent/blob/11cea575561fb7800b5fb6b6cafa56f7a91de11f/Mobile-Agent-v3.5/mobile_use/run_gui_owl_1_5_for_mobile.py)、[图文历史与请求构造](https://github.com/X-PLUG/MobileAgent/blob/11cea575561fb7800b5fb6b6cafa56f7a91de11f/Mobile-Agent-v3.5/mobile_use/utils.py)、[四角色编排](https://github.com/X-PLUG/MobileAgent/blob/11cea575561fb7800b5fb6b6cafa56f7a91de11f/Mobile-Agent-v3.5/android_world_v3.5/android_world/agents/mobile_agent_v3.py)。

原生单模型与四角色可以作为不同系统对照，但不能把两者的费用差异全部归因于 Jev。升级模型、更改规划频率、调整图像输入和设备通道应分组记录。

## 3. Jev 请求费用示例

已核查 `jev-1.13.0` 价格为每百万输入 token $0.042，输出免费；实际使用时以所选模型版本和账户账单为准。Jev 只接收文本/JSON。[TypeSafe 模型与价格](https://docs.typesafe.ai/models)

一次完整输入包括任务、子目标、相关历史、布局树、候选与问题，不能只计算节点文字。以下仅展示 Jev 费用的量级，不代表任务总成本或预测调用次数。

| 完整输入 / 请求 | 单次 Jev 费用 | 假设 20 步、每步选择和验证各一次，共 40 次 |
|---|---:|---:|
| 2,000 token | $0.000084 | $0.00336 |
| 5,000 token | $0.000210 | $0.00840 |
| 10,000 token | $0.000420 | $0.01680 |

规则可直接判定时无需 Jev 核验；等待、重新观察或错误重试可能增加请求。实际选择和验证的输入长度也不必相同，最终按 usage 统计。

## 4. 统一核算方式

```text
单次模型请求费用 = 按供应商 usage 和计费规则计算的输入、缓存及输出费用

任务推理费用 = 所有生成式模型请求费用
             + 所有 Jev 请求费用
             + 所有辅助模型请求费用

任务总费用 = 任务推理费用 + 分摊的服务端、存储和网络费用

每个成功任务分摊费用 = 所有尝试的总费用 / 成功任务数
```

分母为零时报告无成功任务，不输出误导性的平均值。失败尝试、重试、回退和终止轮都应计入。费用币种统一后再比较，记录换算日期和汇率；缓存 token 如何包含在输入统计中按各供应商规则处理，避免重复计费。

实际节省比例可以在取得数据后按 `1 - 改造后费用 / 对照费用` 计算，同时报告成功率、失败类型与任务步数。只降低完成率而减少调用，不能认作有效降本。

| 可能改变成本的因素 | 需要单独记录 |
|---|---|
| Jev 替代动作选择 | 候选覆盖、选择错误、参数来源、视觉回退、两条路径各自费用 |
| 规则/Jev 替代视觉核验 | 规则命中、四态结果、误报成功、等待次数、视觉验证费用 |
| 按需调用 Manager | 实际规划触发原因、过期计划、恢复和额外步数 |
| 历史与布局树裁剪 | 每次输入量、必要上下文丢失、缓存命中与费用 |
| 减少图像上传 | 采集次数、上传次数、图像尺寸/数量与供应商计价 |
| App 名称解析等辅助调用 | 是否走辅助模型、模型版本、请求量和费用 |

节点定位与候选构造优先使用代码。如果后来加入模型生成候选、文本内容或摘要，应作为新增费用记录，不能隐藏在 Jev 节省中。

## 5. 验证方法

沿用[阶段方案](2026-09-22-stages-evaluation-and-flows.md)，在相同任务、初始状态、模型版本、App/系统版本及预算条件下配对比较。先保存原版与提取后 VLM 基线，再逐项开启 Jev 选择、树验证及按需规划，不一次改变所有模块。

每组至少记录：独立判定的任务结果、动作和重试次数、各角色调用与 token、视觉回退、误报成功、端到端延迟，以及全部尝试费用。模型服务延迟、布局采集、执行和页面等待分开统计；截图采集和上传也分别计数。

模型版本、请求协议或供应商变化时重新核算。托管 API 与自部署的成本口径不同；首期采用 API，不把尚未配置的 GPU 利用率或自部署推理成本算入结论。
