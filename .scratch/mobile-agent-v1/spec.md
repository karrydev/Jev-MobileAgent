# Jev-MobileAgent 首版规格

Status: ready-for-agent

2026-09-22：用户已确认测试边界、任务粒度、依赖与延后人工准备。实施进度见[任务索引](index.md)。

## Problem Statement

用户希望通过 Android 手机完成跨应用目标，并逐步减少视觉模型的调用开销。现有 MobileAgent v3.5 提供宿主机驱动的模型与角色能力，但没有本项目需要的独立 App 设备通道、可靠会话与手动恢复机制。仅替换模型无法保证界面观察、真实执行、结果核验和任务完成的一致性。

开发还需要避免多名 Agent 分别完成模块后才发现接口不匹配；用户希望把账号、手机授权和服务器准备延后，让可自动完成的实现与验证先推进。

## Solution

面向单用户、单手机、同一时间一个任务，提供 Android App 与 Python 编排服务。App 负责设备观察、操作和用户控制；服务端保留 v3.5 的生成式能力，逐步引入 Jev 候选选择、四态核验和按需规划。最终在普通服务器运行，用户手机不依赖开发电脑或 ADB。

先交付可重复运行的模拟任务链路与独立判分，再替换为 Android 通道和实际模型。每一阶段都能展示完整行为及其证据，明确区分模拟、模拟器、实际 API 与物理手机结果。首次真实能力联调前才请求必要的用户准备，Jev 和服务器各自在更晚关口请求。

## User Stories

1. 作为用户，我希望在手机上输入一个目标并发起任务，以便让系统代我完成操作。
2. 作为用户，我希望看到手机连接和权限是否可用，以便知道任务能否开始。
3. 作为用户，我希望同一时间只运行一个任务，以便避免多个任务争夺手机。
4. 作为用户，我希望重复提交不会启动重复任务，以便避免重复操作。
5. 作为用户，我希望看到任务运行、暂停、结束与失败状态，以便理解当前进展。
6. 作为用户，我希望看到当前子目标和必要的失败原因，以便决定是否接管。
7. 作为用户，我希望暂停任务后不再派发新动作，以便检查手机现场。
8. 作为用户，我希望取消任务后迟到的模型响应不能继续操作，以便真正结束任务。
9. 作为用户，我希望系统解释暂停时已经在途的动作结果，以便不把暂停理解为撤销已执行操作。
10. 作为用户，我希望断线后任务暂停，以便避免基于失去联系的现场继续操作。
11. 作为用户，我希望通信重连后仍等待我确认，以便自行决定何时恢复自动操作。
12. 作为用户，我希望手机 App 或服务端重启后核对执行历史，以便避免重复产生副作用。
13. 作为用户，我希望系统发现我手动介入或现场失效时暂停，以便我的操作不会与自动执行冲突。
14. 作为用户，我希望恢复前重新观察现场并核对结果，以便继续依据当前状态行动。
15. 作为用户，我希望结果不明的动作不会自动重放，以便避免重复发送、输入或确认。
16. 作为用户，我希望证据不足时系统保持暂停并解释缺口，以便不会被误报为恢复成功。
17. 作为用户，我希望系统利用可访问界面的文字、状态和窗口信息，以便理解当前可操作内容。
18. 作为用户，我希望旧节点和旧观察产生的动作被拒绝，以便不会点击已经变化的目标。
19. 作为用户，我希望重复或乱序命令不会造成重复执行，以便连接波动不会改变任务结果。
20. 作为用户，我希望输入、点击、长按、滑动和系统导航在设备支持时可用，以便覆盖首版任务需要的操作。
21. 作为用户，我希望中文输入保留完整内容，以便无需手工纠正模型或设备桥造成的乱码。
22. 作为用户，我希望旋转、缩放、系统栏和输入法出现后仍正确定位，以便操作落到期望目标。
23. 作为用户，我希望树为空、自绘页面或窗口遮挡时有明确处理，以便系统不会盲目猜测可操作节点。
24. 作为用户，我希望必要时使用视觉回退，以便树信息不足时仍有解决机会。
25. 作为用户，我希望截图不可用或权限撤销时得到明确提示，以便知道为何暂停或无法继续。
26. 作为用户，我希望模型返回未知动作或缺少参数时拒绝执行，以便错误响应不会变成手机操作。
27. 作为用户，我希望 Jev 只选择目标和参数齐全的候选动作，以便选择结果能被确定地执行。
28. 作为用户，我希望自由文本来自我的指令、已知模板或生成式模型，以便闭集选择模型不会被要求编造文本。
29. 作为用户，我希望没有合适候选或选择无效时转视觉或暂停，以便系统不会强行选择错误操作。
30. 作为用户，我希望执行回执与实际效果分别显示，以便知道命令受理并不等于操作成功。
31. 作为用户，我希望动作核验区分 SUCCESS、FAILURE、PENDING 和 UNKNOWN，以便未完成、等待和证据不足不会混为一谈。
32. 作为用户，我希望等待有时间和次数上限，以便任务不会无限卡在加载状态。
33. 作为用户，我希望只有整体完成条件满足时才报告任务完成，以便中间动作成功不会提前结束任务。
34. 作为用户，我希望视觉核验需要前图时已经保留前图，以便核验使用真实的前后证据。
35. 作为用户，我希望计划过期、子目标切换或反复失败时重新规划，以便系统能应对变化。
36. 作为用户，我希望重复循环和预算耗尽会停止或暂停，以便限制无效操作及模型消耗。
37. 作为用户，我希望能回看任务的观察、动作、核验和结束原因，以便理解发生了什么。
38. 作为用户，我希望费用统计包含失败、重试和视觉回退，以便了解真实总消耗。
39. 作为用户，我希望缺失的 usage 和未知费用被明确标注，以便报告不会给出虚假的精度。
40. 作为用户，我希望在 App 内填写自己的模型供应商、endpoint、模型名和 API Key，以便安装 App 后即可配置使用；凭据与设备桥 Token 分开，保存在 App 私有空间，只提交到自己的编排服务，不进入日志或公开轨迹。（按用户后续明确要求修订，替代仅服务端配置。）
41. 作为用户，我希望原始截图、布局树和敏感轨迹留在受控的本地证据环境，以便公开仓库仅含脱敏材料。
42. 作为用户，我希望完成部署后拔掉 USB 并关闭开发机 ADB 仍能运行，以便日常使用只依赖手机与服务器。
43. 作为用户，我希望到实际需要时再准备 API、手机和服务器，以便减少前期参与和等待。
44. 作为维护者，我希望不提供真实凭据就能运行模拟任务和回归检查，以便持续开发。
45. 作为维护者，我希望对同一输入重复执行得到可核对的离线结果，以便定位回归。
46. 作为维护者，我希望评测依据独立的页面状态或任务判据，以便避免让 Agent 自己给自己判成功。
47. 作为维护者，我希望决策输入无法访问参考答案、未来帧和后台真值，以便评测有效。
48. 作为维护者，我希望开发集与留出集按任务或轨迹划分，以便相邻帧不会泄漏答案。
49. 作为维护者，我希望分别保存原真机单模型与 AndroidWorld 四角色基线，以便不会混淆不同入口。
50. 作为维护者，我希望提取角色与裁剪分别验收，以便能定位目录整理与行为改变的影响。
51. 作为维护者，我希望先影子运行 Jev 再受控执行，以便建议质量和真实执行效果分别可测。
52. 作为维护者，我希望选择、核验与规划策略逐项启用，以便识别每项变化的影响。
53. 作为维护者，我希望每次结果关联代码、模型、配置、环境和任务版本，以便别人能够复现。
54. 作为维护者，我希望在明确接口与所有权下并行开发，以便不同实现能按依赖顺序合入。
55. 作为维护者，我希望每张任务交付可演示或可独立核验的行为，以便进度对应真实结果。
56. 作为维护者，我希望来源历史、许可证及移植记录得到保留，以便衍生项目能够持续维护。

## Implementation Decisions

### 已确认的边界

- 首版单用户、单手机、同一时间一个任务；设备端负责观察、执行和用户控制，Python 服务负责 Agent 编排。沿用既有两个 accepted ADR。
- 断线、重启或人工介入后暂停；重新观察、核对历史并经用户确认后恢复。重连只恢复通信，结果不明的命令不自动重放。
- 复用 MobileAgent v3.5。先完成原版双入口实际基线，再提取必要角色，最后裁剪与复验；保留 Git 历史、来源、许可证。
- 首个真实模型里程碑是 App 通道上的仅 VLM 闭环。之后按 Jev 选择、树核验、按需规划的顺序启用策略；每一项都有独立开关和对照。
- Jev 用于闭集选择或分类；生成式模型负责规划、自由文本、摘要和视觉回退。实际供应商协议兼容性需要实测。
- 本地 Markdown 是实施任务追踪器。协作使用独立 worktree 和分支，集成负责人串行管理任务领取、共享接口和合入。
- 用户准备延后到真实能力关口，分别请求 VLM、物理手机、Jev、服务器；尽可能合并相邻请求但不提前要求与当前工作无关的资源。

### 已确认的实现约束

- 用一个任务运行入口贯穿提交目标、获取观察、发出动作、接收回执、重新观察、核验和结束；同一入口可装配模拟设备、Android 设备和回放或真实模型。
- 首张任务只实现一个可验证的模拟动作闭环及最小版本化契约，不预先设计所有未来功能。后续切片按需要扩展契约并附正反样例；共享契约扩展由单一负责人合入，消费者按同版本实现。
- 观察携带设备、窗口、时间、尺寸/旋转、版本、节点引用及能力/缺失原因；节点只在绑定观察内有效。完整动作包含目标、参数、来源和关联观察。
- 设备会话最多一个在途动作；定义任务和命令身份、去重、乱序、暂停、取消、持久化与重启后的核对边界。不承诺物理操作的 exactly-once；无法核对的结果保持 UNKNOWN 并暂停。
- Android 每个切片同时打通 App、协议、服务端呈现与验证；首版 App 提供目标输入、连接/权限状态、任务状态、暂停、取消和恢复所需的最小界面，不另增产品面板。
- 坐标转换统一处理屏幕尺寸、模型缩放、旋转和窗口偏移。动作前图按原视觉核验需要预留；采集与上传分别计数，图像始终关联同一观察版本。
- 回执只说明受理/执行事实；四态核验描述动作后置条件；任务完成另看整体目标。PENDING 有界等待，UNKNOWN 走补充证据、视觉或暂停。
- 最小任务证据从第一个闭环产生；后续集中补齐失败、重试、延迟、usage 与费用。原始个人数据及凭据不进入公开仓库。
- 真实 API、物理手机和服务器验证前分别准备可直接运行的探针、安装包、检查清单及脱敏报告模板，用户仅提供无法代办的访问或授权。
- 传输、认证、存储、具体 schema、工具链版本和工程布局由相关切片的负责人结合现有环境决定并记录；这些未定技术细节不伪装成已批准选型。
- 模拟模式必须显式选择，缺失真实能力时明确失败或待验证；生产运行不静默切换模拟实现。

## Testing Decisions

### 主测试入口

以任务运行入口作为主要行为测试边界：提交目标与初始条件，观察任务状态、设备端可见副作用、动作核验、独立终局判分及轨迹。测试断言外部行为，不锁定内部类、私有方法或角色间调用次数。

通过同一个任务入口替换外部设备与模型依赖：早期使用模拟设备和合成响应；随后 Android 模拟器与回放响应；最后实际模型与物理手机。同一套行为用例尽量复用，报告清楚区分证据层级。

### 必要的外部边界与现有先例

- Android 与网络/操作系统的边界需要实际 App 测试，覆盖 Accessibility 能力、输入法、多窗口、旋转、权限撤销和截图限制；模拟结果不能证明物理手机 ROM 行为。
- 模型供应商边界需要有限的真实请求，验证多图、中文、角色提示词、动作格式、错误与 usage；回放只证明客户端控制逻辑。
- 现有 AndroidWorld TaskEval 的初始化、is_successful 与清理流程可作为独立判分先例，复用具体任务的判据。基类 is_successful 在初始化检查后默认返回 1.0，不能直接作为通用成功判据。
- 现有 MobileAgentV3_M3A 的 reset/step 可用于原四角色行为对照；其运行依赖 AndroidWorld 环境，不能直接当作本项目已实现的 App 接口或端到端测试。

### 验证范围

1. 模拟任务完整链路：正常完成、格式无效、预算耗尽、动作无效果、任务未完成以及状态/证据可追踪。
2. 动作一致性：旧观察/节点拒绝、未知或缺参动作拒绝、重复/乱序处理、取消后迟到响应、在途动作结果核对。
3. 恢复：发送前、设备执行后回执前、回执后核验前的中断；双端重启、人工介入；重连保持暂停，证据不足不重放。
4. App 行为：中文输入、节点与手势、窗口/输入法/旋转、空树、截图不可用、授权失效；同时检查服务端所见状态与实际页面。
5. 选择与核验：候选完整性、无候选、非法候选 ID、等价动作、四态标签、误报成功、有限等待和视觉回退。
6. 规划：子目标切换、异常、计划失效、循环与长任务；以行为结果和预算为依据，不测试私有调度函数。
7. 评测：独立逐步/终局真值、开发/留出隔离、全部尝试纳入费用、usage 缺失明确标注。先冻结任务、重复次数、预算与回归放行规则，再运行实际对照；这些数值由评测工作提出，不在本规格中虚构。
8. 交付：最终集成版本重新部署并重建 App，拔掉 USB、停止开发机 ADB 和本地编排后完成约定任务及中断恢复。

模拟、模拟器与真机分别报告。原版真机单模型、原版四角色、提取后参考设备后端、App+VLM、加选择、加核验、加按需规划分别记录，不能把入口差异解释为优化收益。现有源码先例尚未在本轮执行验证。

## Out of Scope

- 多用户、多设备调度、同机多任务并发；应用商店发布。
- 手机内完整模型编排、离线大模型、GPU 采购、模型训练。
- 以 root、Shizuku 或用户长期连接 ADB 为运行前提。
- 中断后自动恢复、未知命令自动重放、无证据的成功报告。
- 提前承诺成功率、延迟或费用提升；把 Mock、影子建议或构建成功当成真实能力通过。
- 首个里程碑前搭建完整 MobileWorld；它作为后续扩展覆盖，不阻塞 AndroidWorld 与自建受控样例。
- 未审查许可即引入第三方设备端实现；替用户注册、付费或操作私人账号。

## Further Notes

本规格汇总已有讨论与工程文档，未新增产品范围。当前仅文档和初始化已完成；所有实现与运行结论均待验证。

测试边界与任务拆分已获确认，正式发布新的本地执行规格与独立任务文件。既有 21 项作为来源和范围覆盖依据，不因本次拆分被记为完成；新旧编号使用不同任务目录，发布时统一导航与协作入口，避免双重领取。

本规格不替代领域词汇、既有 ADR 或研究证据。若实现需要改变已确认边界，记录具体冲突后再讨论。
