## Acceptance criteria

- [ ] 安装 APK 后可在 App 配置 VLM 与 Jev 的供应商端点、模型和各自 Key，保存、修改、清除；VLM 单独运行不强制提供 Jev Key。凭据用 Android Keystore 支持的加密存储，界面掩码显示，不进入日志/导出/备份明文或 APK；旧明文模型配置提供迁移或明确重新输入路径。开发 env 只供测试准备。
- [ ] 产品入口不要求桥地址、设备桥 Token 或连接 Python 服务。App 内任务入口完成目标→观察/前图→必要角色调用→合法动作→回执/后图→独立核验→任务结束；任务和证据落在手机本地，沿用单任务、观察绑定、坐标转换与动作去重约束。
- [ ] 直接请求配置的供应商 HTTPS API。最小相关回放覆盖成功、中文、多图、格式错误、401/429、网络错误、超时、迟到响应及 usage 缺失；预算与步数有界，失败/重试计费，未知用量不记零。不新建代理服务，也不把 Key 转发到设备桥。
- [ ] 保留既有角色、提示词与决策行为作为移植对照，不在本票顺带改变为按需规划。切换到目标 App 后仍可执行，暂停/取消入口可达；暂停和取消能阻止后续模型结果派发，系统终止/权限失效时停止新动作。
- [ ] 在真实手机只使用 App 及模型供应商完成已冻结受控任务，至少覆盖中文输入和视觉动作，按独立判据核对页面结果。项目 Python 服务停止、ADB reverse/无线调试关闭、USB 断开；执行期间无宿主辅助。以手机日志/报告证明请求由 App 发出。
- [ ] 生成新的“独立 App+VLM”基线，记录代码/提示词/模型/任务/预算与失败。保持旧 19/20 和原版/提取版对照，说明入口迁移影响，不把它计作 Jev 策略收益。

## 范围边界

采用现有 Android 工程承载最小实现，不另建通用 Agent 平台、Python 运行时或本机 HTTP 桥。Python 代码和部署脚本暂保留为开发参考，不为移植提前做大规模清理。Android 系统允许的执行服务与本地持久化由实现者结合现有代码选定并验证；不承诺锁屏自动操作或无限后台常驻。

## 交付证据

记录最终合入 SHA、APK/模型/配置版本、验证命令、实际结果和未验证项。模型探针、桥接 App、模拟响应与手机内真实闭环分别报告；既有证据只在覆盖对象未改变时沿用。测试结束或失败后锁屏。
