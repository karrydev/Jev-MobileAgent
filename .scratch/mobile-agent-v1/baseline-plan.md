# 首轮双入口基线冻结方案

版本：2026-09-23 / v1。依据用户“全部由你来控制”、真机测试与总预算 ¥10 的授权，由协调者选择项目受控页和独立模拟器任务，不要求私人账号。

## 样本与判分

| 入口 | 中文目标 | 初始状态 | 独立成功判据 |
| --- | --- | --- | --- |
| 原 mobile_use / OnePlus 8T | 点击 Toggle controlled state，使状态变为 completed | 项目 ControlledPageActivity，ready，竖屏 | 操作后项目观察的状态文字严格等于 Controlled action state: completed；保留前后截图 |
| 原 AndroidWorld 四角色 / 独立 API 33 Pixel 6 | 把屏幕亮度调至最高 | SystemBrightnessMax.initialize_task 初始化低亮度 | 使用具体 SystemBrightnessMax.is_successful 的系统设置判据，不使用基类默认成功 |

每入口首轮 1 次，最多 5 步，无自动重试。每次模型响应上限 1024 tokens；每入口费用保守预留上限 ¥1，总预算累计仍不得超过 ¥10。设置网络超时，遇到未知 usage 则停止进一步付费请求并记录费用未知。失败、准备后的真实请求、人工取消都记录，不能删掉失败重跑后只报告成功。

## 运行与放行

先满足任务 15 的兼容性门槛，再开始任务 16。启动前记录代码 SHA、原版来源文件 SHA-256、模型与完整请求配置、提示词、APK SHA、设备/模拟器版本、初始状态和预算。原版与最小适配版本分别编号，坐标说明、图片传输、屏幕尺寸等必要修复独立记录，不把适配结果标成未经修改的原版结果。

真实手机仅允许项目受控页点击与系统导航；模型若尝试离开受控范围或执行未授权动作，停止并记录失败。AndroidWorld 仅操作专用模拟器。初始页面准备由协调者完成，Agent 决策只读当时画面与任务指令，不能读取后台判分真值。

每次结束后采集独立判分与全部 usage；手机不自动恢复失败任务。此方案是小样本可运行性检查，不用于宣称成功率或优化收益。两入口都需实际执行，并取得完整轨迹、来源与有效独立判分，才允许进入角色提取；任务成功与否按上述判据分别报告。环境无法运行或判分无效时，任务 16 保持未完成。

2026-09-23 用户补充：继续按 code-this 推进，减少过度设计；仅补当前验收实际需要的适配，优先复用上游。每轮真机测试结束后执行锁屏并确认屏幕休眠；等待代码开发或审查期间也不让手机持续亮屏。

基线采集放行说明：任务 16 的验收要求是原版可运行、独立判分和全部失败有记录，不是要求模型在所有样本上成功。协调者初稿额外加入的“所有任务成功才提取”已移除；目标成功判据、5 步上限和失败结果保持不变，禁止把该调整解释为亮度任务通过。后续提取/裁剪必须比较真实任务结果和轨迹，保留已知失败。
