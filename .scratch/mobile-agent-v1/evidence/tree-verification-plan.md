## 配对与独立标签

同一最终APK、OnePlus 8T / Android14、GUI-Plus gui-plus-2026-02-26、TypeSafe jev-1.13.0。两侧保持受控选择开启、影子关闭、原规划频率，每个目标分别 tree-off/tree-on 各一次。初始输入为空、蓝框未点击、竖屏、软键盘收起，任务上限5步/25 VLM请求/¥1。中文目标仍为“在中文输入框中输入‘独立手机测试成功’”（运行时用现有预设的中文双引号），视觉目标仍为现有蓝框预设。开始前重新进入页面复位。

正常中文输入的精确文本后置条件为SUCCESS；蓝框节点候选不覆盖的实际视觉变化在树证据层应为UNKNOWN，不凭树变化报SUCCESS，补充真实前后图后才能按视觉证据继续。每个配对目标都必须独立成功，树模式不得新增错误动作或提前终止；只有核验策略变化。

其他真实受控负例各一次：加载状态（PENDING后有界重观察，达到上限转明确回退或暂停）；受理但无效果的动作（不能报SUCCESS）；相似但不精确的文本（不能报SUCCESS）；视觉核验所需截图不可用（UNKNOWN并安全暂停，不能补拍前图）。若最终fixture没有能力明确构造某条真值，记录缺口而非用合成重放冒充真实验证。

动作前后真实页面与受控副作用/时序是独立标签来源；回执只是执行事实，最终任务成功不是每步核验真值。报告每次规则/Jev/视觉决定、PENDING轮数、四态混淆与误报SUCCESS，记录abstain及后续视觉分支，不将UNKNOWN回退伪装成树判断正确。策略输入不得携带独立答案、未来帧或后台判分数据。

## 请求与放行

本轮首批最多8项手机任务，无自动重试；每次先在总账预留，所有失败/取消/重试入账。累计仍限¥10，本轮额外消耗和未知费用预留最多¥2，达到本轮上限先停止进一步调用。Jev当前累计12次。第二批有界累计上限40（最多新增28次），每任务仍最多5次；保留原计数和全部费用，不清零。理由：24在原选择请求外加入核验，同一批8项配对/负例仅余8次不足以覆盖；主协调在首个24调用前明确此边界。¥2阶段/¥10累计预算优先于请求次数上限；达到任一上限即暂停。

每角色模型请求、截图采集和上传分别记录。保持真实前图；不得以没有Reflector请求就推导未采集截图。保留所有原始尝试，仅在具体产品修复或环境变化后新编号重试。对照未通过或出现未处理的误报成功则默认关闭新策略，票保持in-progress。

## Debug 场景约束

受控页故障区与正常场景隔离，默认折叠/单独入口；正常中文/蓝框配对不因新增按钮改变页面布局。模型通过同一任务入口执行目标动作，协调者只预置场景并启动。延迟按钮展示加载及稍后完成，无效果按钮受理但没有预期可见变化；相似文本场景需让目标输入动作的实际结果是近似值，不把“主动填写近似值”这一本应成功的操作错标失败。一次性AFTER故障走真实截图失败路径，保留真实前图，不能返回合成图片。

通用调试目标若不受现有终局判据支持，应保持NEEDS_REVIEW；此类用例以逐步四态和可见结果评估，不扩写通用终局框架。具体按钮/目标/延迟和等待上限在实现完成后、首个调用前记录。

## 冻结场景入口与时点

MainActivity 的独立 Debug 入口打开 TreeVerificationFixtureActivity；正常 ControlledPageActivity 不新增控件。

- 加载：目标 `点击“延迟加载按钮”一次，等待页面显示“加载完成”，不要重复点击。`；真实按钮显示“加载中”1200ms，然后“加载完成”。首个加载观察标签PENDING，600ms一次最多两次等待；超限转UNKNOWN，再补证据或暂停。若观察延迟错过加载，不冒称覆盖PENDING，保留尝试并以明确环境变化另编号。
- 无效果：目标 `点击“无效果按钮”一次，不要重复。`；真实click监听不改页面，树证据标签UNKNOWN，不能仅凭受理报SUCCESS。
- 相似文本：目标 `在中文输入框中输入“独立手机测试成功”`；实际输入框 LengthFilter(7) 接受输入但显示七字近似值“独立手机测试成”，精确文本条件为FAILURE。未来结果/真值不注入策略。
- 截图失败：目标 `点击自绘区域蓝框中心`；启动前只打开一次性“下次AFTER截图不可用”，运行时走真实onError路径，不生成伪图片。真实BEFORE保留、AFTER缺失，核验UNKNOWN并暂停/NEEDS_REVIEW；页面真实副作用单独取证。

所有目标由本机任务入口驱动，主协调不手点目标控件。标签按实际捕获时点判分，模型的自述不作为真值。
