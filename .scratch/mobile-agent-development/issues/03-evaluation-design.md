## 目标

后续实验有一致的任务和判分口径。本任务尚未开始，文中能力均为待交付。

## 前置依赖

无其他实施任务依赖。领取仍须遵守共享文件和设备预约约定。

## 修改范围

eval 中任务清单、人工 rubrics、合成观察与标注规范。超出范围先与对应负责人协调；根配置和契约不由消费者自行修改。

## 实施与产物

1. 选择原真机单模型与 AndroidWorld 四角色各自的可复现任务，定义起始状态、版本、目标和终局判据；中文真机任务由用户确认。
2. 设计可控测试页面/样例，覆盖输入、滚动、多窗口、空树、相似文字、加载、无效点击、旋转和截图不可用。
3. 冻结首轮任务集合、重复次数、预算、允许回归及放行规则的填写方式；区分环境失败与 Agent 失败，按任务/轨迹划分开发与留出集。

## 验收

- [ ] 每个样例有来源和预期结果；任务成功不依赖 Agent 自报或原 VLM 判断。
- [ ] 动作后置条件和任务终局真值分别保存，不能将终局失败传播成每一步 FAILURE。
- [ ] 数据不使用未来帧、答案或 evaluator 后台真值构造决策候选；初版可用合成样例，但注明非真实覆盖证据。

## 证据与交接

按[协作约定](../../../docs/parallel-development.md)记录最终 SHA、契约/模型/设备版本、验证命令、结果和未验证项。原始私人内容与凭据保留在指定运行环境；仓库只留脱敏摘要和可复现说明。实施任务完成但尚未合入或缺少必要实测时，Execution 保持 in-progress。
